# 第三关泡泡阵性能修复

已修复静止阵列随其他界面动画反复排序、重建和上传网格的问题。保持原分辨率、3600 个泡泡、主体与高光两层、落地挤压动画和遮挡顺序。

## 实现

- 泡泡阵和边框使用独立的子 Canvas，仍位于护栏、角色、弹道和 HUD 之前。角色和提示动画不会使整片阵列重新上传。
- 静止时保留网格；下落、增删泡泡、阵列推进、震动、入场、炸弹高亮、换关和屏幕适配变化时刷新。
- 落位检查使用精确比较，保留细小移动和最后一帧挤压恢复；已经落稳的泡泡跳过重复插值计算。
- 需要刷新时，已有正确遮挡顺序的阵列跳过完整排序；流动或补充造成顺序变化时沿用原排序规则。
- 未修改关卡、玩法或受保护的模型逻辑。783 个受保护文件的哈希检查通过。

代码：`UnityProject/Assets/Flightbeat/Garden/PixelWingGame.GardenBoard.cs`、`PixelWingGame.GardenSand.cs`、`PixelWingGame.Garden.cs`、`PixelWingGame.GardenUi.cs`。

同一台桌面设备、Chrome、390×844 CSS 视口、DPR 2、实际画布 780×1688。直接进入第三关，进场完成后停在 Ready 状态，分别采样 12 秒。

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 实际可见泡泡 | 3600 | 3600 |
| 主线程任务时间／帧 | 5.23 ms | 1.92 ms |
| 网格 buffer 提交字节／帧 | 1.475 MiB | 0.075 MiB |
| WebGL drawElements 调用／帧（约） | 9 | 10 |
| rAF 帧率 | 60 | 60 |

主线程任务时间减少约 **63%**，网格上传量减少约 **95%**；独立阵列增加一批绘制调用，换取静止网格不再随 UI 重建。以上是本地 Ready 场景测量，不代表所有战斗场景都减少同样比例，也不是反馈者微信手机上的实测值。
