## 是否编译

| 用户指令 | 执行方式 |
| --- | --- |
| “发布”“部署”“更新线上”“发布最新版本”等，没有明确要求编译 | 直接发布现有 WebGL 产物 |
| “编译并发布”“重新打包后发布”“构建后部署”等，明确要求编译 | 先执行构建，成功后发布新产物 |

直接发布时，不运行 Unity 构建、图集生成或其他会重新生成产物的步骤。即使源码或美术资源有新修改，也不自动编译；“最新”默认指现有的已编译产物。若产物缺失或不完整，说明具体问题并停止发布，等待补齐产物或用户明确要求编译。

仅在发布任务明确要求编译时，从仓库根目录执行：

```bash
bash scripts/r1v3/build.sh
```

该脚本会替换固定产物目录 `Builds/WebGL/GardenR1-bubble/`。编译失败则停止，不发布失败或残缺的输出。

## 发布步骤

1. 确认本次是否明确要求编译，并按上一节选择流程。检查产物中的 `index.html`、`Build/` 及页面引用的配套资源完整，确认没有构建进程正在改写该目录。产物中有 `LEVELS_TEST_BUILD.txt`（`R1_LEVELS_TEST=1` 测试构建，含未验收的 B-test 关卡）时**不得发布**，先清除测试通道并重新正式构建。
2. 生成本次版本号，记录产物时间、文件清单和校验值，结合构建来源、开发记录和上次成功发布记录，整理本次游戏更新内容。当前固定目录的发布记录保存在本地 `Builds/releases/toy/{version}.json`，包含版本、发布时间、是否编译、产物路径、文件校验值、游戏更新内容及其依据、最终地址和验证结果。
3. 将产物目录内的内容完整上传到 `/www/wwwroot/minigame/bubble/.toy.staging-{version}/`，校验上传结果。上线后的入口应为 `bubble/toy/index.html`，不额外嵌套一层本地产物目录名。
4. 保留现在线上目录作为待回退版本，将完整暂存目录切换到 `bubble/toy`。切换和验证期间，保留原有上一版备份，直到新版本验证通过。
5. 访问本次带版本参数的地址，检查入口及关键资源请求成功、WebGL 能正常加载进入游戏。首页的 `?v=` 用于标识发布版本；资源是否更新仍须核对实际资源 URL 和缓存行为。
6. 验证通过后，将本次替换下来的线上版本保留为 `bubble/toy.prev`，删除更早的本项目发布备份、临时目录及上传包，并更新发布记录为成功。
7. 按下文格式报告本次游戏更新内容、实际版本号和可点击的访问地址。

同一项目的发布应串行执行。上传或校验失败时不切换线上目录；切换后验证失败时恢复发布前的线上版本及备份关系，并报告失败情况。首次发布没有上一版时，不创建空备份。

## 目录保留规则

自 2026 年 10 月 24 日起，默认发布到固定路径 `/www/wwwroot/minigame/bubble/toy/`。将产物内容直接放入其中，不再套版本号或 `GardenR1-bubble` 子目录。文件自身需要的 `Build/`、`TemplateData/` 等目录按原结构保留。

成功后保留 `toy/` 当前版和同级 `toy.prev/` 上一版。目标此前为空时不创建空备份。暂存和上传包放在 `bubble/` 下的隐藏路径，验证通过后清理，只轮换此发布链的备份。

原 `paopao` 系列目录、`paopao_v3` 及独立临时版本均保留，不随 `toy` 发布覆盖或清理。`paopao_v3` 继续保留原独立访问地址。

用户另行明确要求临时发布时，使用独立目录并在发布记录中注明，不自动切换正式目标；临时发布记录位于 `Builds/releases/temporary/`，固定 `toy` 发布记录位于 `Builds/releases/toy/`，不同发布链分别比较上次版本。

## 发布完成后的反馈

每次发布完成，必须以“本次更新”说明相对上一版实际发生的游戏变化，并给出带 `?v={version}` 的完整地址。版本号必须替换为本次实际值。

- 内容涵盖本次实际涉及的游戏逻辑、玩法、界面、美术、动画、音乐音效和问题修复；优先写玩家能感知的变化，不必凑齐所有类别。
- 用“调整了什么、现在怎样”概述。例如，确有对应改动时写“炸弹确认按钮移到队列区，新增取消按钮，减少遮挡和误触”。
- “更新资源包”“更新运行框架”“更新 WebAssembly”“变更了几个文件”等属于技术文件差异，保留在发布记录中，不作为游戏更新摘要。
- 以产物对应的构建来源、开发记录、代码或资源差异及上次成功发布记录交叉核对。上一版已包含的功能，以及尚未编译进入本次产物的源码修改，不列为本次更新；不能仅按当前 Git HEAD 推断产物内容。

如果无法可靠确认具体游戏变化，明确说明“本次游戏更新内容暂无法确认”，不要编造，也不要用文件变化代替。产物与上次一致时说明“重新发布相同版本，无游戏内容更新”。

反馈格式：

```text
发布完成
版本：{version}
方式：直接发布现有 WebGL 产物 / 编译后发布（填写实际方式）

本次更新：
- {游戏逻辑、玩法或表现的具体变化及效果}
- {本次实际修复的问题，没有则省略}

访问地址：http://minigame.cornor.cn/bubble/toy/?v={version}
备份：保留上一版 bubble/toy.prev，更早版本已清理（首次发布则说明无上一版）
验证：{实际验证结果}
```

此处为反馈模板，首次实际发布后再生成发布记录。本文件建立于 2026 年 10 月 18 日。
