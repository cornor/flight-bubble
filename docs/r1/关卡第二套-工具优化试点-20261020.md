## 1. 改了什么

### 转换候选和精细取景

`scripts/levels_b/convert.py`、新增 `conversion_guards.py`：

1. 候选必须同时满足逐色改动上限、总改动上限、D10/D20，才排在通过组。原实现排序只看结构、总改动的十格分段等，选完后才检查逐色限制，存在漏选风险。
2. 通过组按精确改动格数排序；全部失败时按违规项数、相对超限程度展示接近目标的方案，不把它当通过。
3. 每种模式先试两档缩放，无全部通过的候选时扩展其他档。补齐数量的理论下界已超限时剪枝，减少无意义运算。
4. 新增 `--fine-search`：缩放步长 0.005、平移步长 1 格，范围仍为 0.8–1.1 倍、±3 格。
5. 转换退出码 0 现在要求补齐和结构都通过；2 表示生成了精确色数但检查未过；1 表示输入错误或当前算法未找到受保护条件下的精确补齐结果。

### 主体和补齐保护

1. 原先小部件只减分、仍可被改掉；现在小于 15 格的连通色块、细轮廓端点为硬保护。
2. 每个格子最多补色一次，避免已经调整的格子反复充当中间颜色。
3. 新增绑定源图 SHA-256 的保护配置，示例在 `Art/levels-b/constraints/`：
   - `subjectRects` 明确哪些主体必须完整，拦截会裁掉主体的取景；
   - `protectRects` 锁定眼睛、嘴、触手、船头船尾等区域；
   - `editableRects` 可选，限定允许补色的区域；
   - `recolorFrom` 可选，限定某种颜色只能从哪些原色扩展。章鱼的玫色斑纹只能扩展到肤色，不能跨过轮廓长到背景里。
4. 默认把边框主色以外的部分都当作前景，较保守；复杂海面、地景需要人工明确主体范围。矩形来自人工看图，工具不能证明矩形覆盖了所有语义上的主体。
5. 每张报告保留配置、配置哈希、候选预算和拒绝数量。`screen.py` 支持配置目录，转换失败另存 `errors.json`。

补齐仍是启发式搜索，不能保证有解必找到，也不能自动证明画面好看。失败时不牺牲保护区，不把失败输出登记为可用。非正方形图的 `--fit crop` 仍属于显式预处理；取景保护针对其后的图，报告用 `sourceCropped` 单列这种情况。

### 对局诊断

`UnityProject/Assets/Flightbeat/Editor/LevelsBDifficultyChecks.cs`、`evaluate.py`、新增 `diagnose.py`、`check_trace.py`：

- `--trace` 记录开局前 20 次决策，以及首次游戏卡住提示、复活、终局前最多 16 次决策；快照包括队首、上阵成员、前排逐列颜色、已预订目标、空位、实际选择和出战结果。
- 游戏卡住判定仍用 `Battle.Stalled`，不新增卡住计时。机器人有空位却没有选择队员时仅加观察事件。
- 不调用有副作用的 `ExposedAt` / `SuggestedQueue`，不额外消耗随机数；直接读前排数组。暴露列数诊断只适用于这里的空装备、无穿透配置。
- `--no-manifest` 支持不改清单的复跑；`--candidate-dir` 支持独立候选目录，强制配合前者。
- Unity 返回失败或总报告未成功时，禁止写评估通过状态。
- `check_trace.py` 用真实 Unity 对照日志开关，比较除日志和用例名之外的全部结果字段。
